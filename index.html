§01
The disciplines

Three crafts.
Practised in depth.

Depth beats breadth. I work in a tight set of disciplines where I know what good looks like — and where I've made enough mistakes to recognise the bad ones early.

01 — Discipline
/api

API & Backend Engineering

Production-grade REST and GraphQL APIs in Django or FastAPI. Designed for performance from day one — proper serialisation, DB query budgets, caching layers, and auth systems that don't leak.

Django DRF FastAPI PostgreSQL Redis OAuth2 / JWT
02 — Discipline
/aws

AWS Cloud Architecture

Right-sized, cost-aware AWS infrastructure that scales on demand and costs sensibly when it doesn't. ECS deployments, RDS tuning, serverless pipelines — or a full Terraform-based setup built from scratch.

ECS / EKS RDS / Aurora Lambda Terraform CloudFormation
03 — Discipline
/ops

Async Systems & DevOps

Task queues, event-driven pipelines, background workers, and CI/CD that deploys without drama. Built with Celery, SQS, or custom patterns — your web process stays fast, your queue handles the weight.

Celery AWS SQS Docker GitHub Actions Nginx / Gunicorn

§05
The engineer

A profile of
the writer.

Backend engineer, two-plus years in production. Builds in public. Writes things down. Available for remote work.

Hi — I'm Awais Yasin. I'm a backend engineer with 2+ years building production systems in Python and Django: subscription billing, async task pipelines, AI integrations, and cloud deployments.

I've built three full backends independently from schema to production, and I'm looking for a remote role with an international team where I can go deep on backend systems and grow alongside engineers who care about the craft.

I think in data flows and failure modes before I write a line of code. APIs are contracts; I treat them that way. I write down what I've decided and why, and I leave systems better documented than I found them.

i.
Systems thinker
Data flows and failure modes come before the first line of code. APIs are contracts — I treat them that way.
ii.
Async-native communicator
Remote-first from the start. Written updates, clear PRs, and status that doesn't require a meeting to understand.
iii.
Ownership mentality
I don't wait to be told what's broken. If I see a problem, I flag it, scope a fix, and ship it.
